API reference

Every surface an integration or automation can build on, generated from the shipping code. Labels and descriptions are the same strings Home Assistant shows in its own dialogs, so this page and the UI never disagree.

New to this? Start with the integration guide, which walks through calling a service and reacting to its event.

Surface coverage​

Every kind of integration surface Home Assistant offers, and the status of each one here. The rows that say not applicable or deferred are the useful ones: a list of what exists cannot tell you what is missing.

SurfaceStatusNotes
Actions (services)PublishedEach operation that changes or exports library data is a home_keeper_library.* service.
Bus eventsPublishedEach state change fires a home_keeper_library_<noun>_<verb> event with a payload from a pure builder.
Device triggersNot applicableThe library has 1 service device and no device per book for a trigger.
Device conditionsNot applicableThe sensors and the to-do lists give the state that a condition reads.
Device actionsNot applicableThe services cover each operation and take a book id directly.
Entity platformsPublishedA sensor platform with library and per-person counts, and a per-person todo list of the books to read.
Entity attributesPublishedThe per-person sensors give the yearly goal, the pages and the titles.
Config entry optionsPublishedThe currency of the prices and values of the copies.
Config flowPublishedA single-instance setup flow with a currency field.
Websocket commandsInternalThe tab and the card read the state and call the twin of each service.
HTTP routesInternalA static path for the bundles, and the cover upload and cover views.
DiagnosticsPublishedThe config entry gives a diagnostics download, with names and notes redacted.
Reauth / reconfigure flowsNot applicableThe storage is local and needs no credentials.
Repairs / issue registryPublishedAn issue shows when Home Keeper is missing, not set up or too old for the tab.
DiscoveryNot applicableNo device or service on the network is a library.
Home Keeper panel tabInternalThe admin UI is a tab in the Home Keeper panel, registered through the Python API of Home Keeper.

Actions​

Every operation that changes or exports data is a Home Assistant action, so automations, scripts, voice assistants and other integrations all reach it the same way. Guard each call with hass.services.has_service("home_keeper_library", "<action>") so your integration still works when this one is not installed.

Events​

The integration fires a bus event for every observable state change. Names follow home_keeper_library_<noun>_<verb>. For when each one fires in context, and worked automations, see the events guide.

EventFires whenPayloadAdds
home_keeper_library_room_addedA room was added.room
home_keeper_library_room_updatedA room changed.roomchanged_fields
home_keeper_library_room_removedA room was deleted.room
home_keeper_library_bookcase_addedA bookcase was added.bookcase
home_keeper_library_bookcase_updatedA bookcase changed.bookcasechanged_fields
home_keeper_library_bookcase_removedA bookcase was deleted.bookcase
home_keeper_library_shelf_addedA shelf was added.shelf
home_keeper_library_shelf_updatedA shelf changed.shelfchanged_fields
home_keeper_library_shelf_removedA shelf was deleted.shelf
home_keeper_library_book_addedA book was added.book
home_keeper_library_book_updatedThe fields, the cover or the wishlist entry of a book changed.bookchanged_fields
home_keeper_library_book_removedA book was deleted, with its copies, reading rows and loans.book
home_keeper_library_copy_addedA copy of a book was added.bookcopy_id, shelf_id
home_keeper_library_copy_movedA copy moved to another shelf, or off its shelf.bookcopy_id, shelf_id, previous_shelf_id
home_keeper_library_copy_updatedThe fields of a copy changed, other than its shelf.bookcopy_id, shelf_id, changed_fields
home_keeper_library_copy_removedA copy was deleted.bookcopy_id, shelf_id
home_keeper_library_reading_changedThe reading row of a person changed. status is None for a removed row.bookstatus, previous_status
home_keeper_library_reading_updatedThe rating, page, dates, count or notes of a reading row changed, and the status stayed. Names the fields, never the notes.bookstatus, changed_fields
home_keeper_library_book_finishedThe reading status of a person became read.bookfinished, rating, read_count
home_keeper_library_loan_startedA book was lent or borrowed.bookloan_id, direction, copy_id, party, started, due, returned
home_keeper_library_loan_returnedA loan was returned.bookloan_id, direction, copy_id, party, started, due, returned
home_keeper_library_loan_updatedThe party, the dates, the format or the note of a loan changed.bookloan_id, direction, copy_id, party, started, due, returned, changed_fields
home_keeper_library_loan_removedA loan was deleted.bookloan_id, direction, copy_id, party, started, due, returned
home_keeper_library_loan_overdueAn open loan passed its due date. Fires once for each due date.bookloan_id, direction, copy_id, party, started, due, returned
home_keeper_library_wishlist_addedA book was added to a wishlist.bookbuy, bought

EventReaction

Entities​

The integration's state is readable as ordinary entities, so most automations never need to call an action to find something out.

sensor​

Entities: Books (books), Loans out (loans_out), Loans overdue (loans_overdue), {person} books read this year (books_read_this_year), {person} reading now (reading_now).
